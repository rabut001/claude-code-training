# 和訳のルール

`ja` を書くときのルールです（共通の取り決め）。訳語の対応表は `docs/glossary.md` にあります。

## 1. いちばん大事なこと

- **答えのヒントを足さない、消さない。** 原文にない説明を足したり、ぼかしたりしない。
- **選択肢どうしの長さのバランスを崩さない。** 正解の選択肢だけを丁寧に訳して長くしない。誤答の選択肢も同じ密度で訳す。
  （長さで正解が分かってしまうと、練習問題として役に立たなくなります）
- **意味を変えない。** 原文が誤っていると思っても、訳では直さない。`docs/tasks/` の作業メモに報告する。

## 2. 文体

| 対象 | 文体 | 例 |
|---|---|---|
| 問題文 | です・ます調 | 「次に何をすべきですか？」 |
| 選択肢 | 常体（だ・である調）。原文が名詞句なら体言止め | 「要求されたツールを実行し、対応する `tool_result` を含むユーザーターンを送る」 |
| `note`・解説 | です・ます調 | 「…のため、API が対応関係を判断できません。」 |

- 選択肢の文末の句点は、1問の中でそろえる（付けるなら全部に付ける）。
- 「You」「Your team」などの主語は、自然に省略してよい（「あなたのチームは」と直訳しなくてよい）。
- 「(Select 2)」「Which two…」は「（2つ選択）」「正しいものを2つ選んでください」とする。

## 3. 英語のまま残すもの

- API・パラメータ・フィールド・値：`tool_use`、`tool_result`、`stop_reason`、`max_tokens`、`tool_choice`、`system`、`end_turn` など
- 製品名・機能名：Claude、Claude Code、Messages API、Message Batches API、Agent SDK、MCP、Skills など
- モデル名、ファイル名（`CLAUDE.md`、`.claude/settings.json`）、CLI のコマンドやフラグ、HTTP ステータス（`429`）
- 原文でバッククォートに囲まれている部分は、そのまま残す。原文で囲まれていない識別子も、訳さずに残す（バッククォートは足さない）

## 4. 表記

- 句読点は全角の「、」「。」。かっこは、日本語を囲むときは全角（　）、コードを囲むときは半角 ( ) 。
- 数字・英字は半角。数字と単位のあいだにスペースは入れない（「40,000トークン」）。
- カタカナ語の長音は付ける（「サーバー」「ユーザー」「パラメーター」）。
- 訳語は `docs/glossary.md` に合わせる。新しい用語を訳したら、glossary に追記する。

## 5. 作業の流れ

1. `ja` を `{ "status": "todo" }` から、`question`・`options`・`explanation` を埋めた形にする。
2. `status` を `draft` にする（`reviewed` はユーザーが付ける）。
3. `./dev check` を通す。
4. 分野ごとにコミットする（例：「CCDV-F d2 を和訳（59問）」）。
